# Admin User Management Feature

## Context

The codebase already has:

- Admin routes at `/admin` with user listing (src/routes/admin.tsx)
- Backend API endpoints for user CRUD operations (src/server/api/routes/admin.ts)
- Database schema with `users` table (is_admin flag) and `subscriptions` table (tier, status, billing info)
- The admin route **already fetches subscription data** (tier, status, billing_interval, price, Stripe IDs) but **doesn't display it in the UI**

**Current gap:** The admin dashboard shows users but doesn't display subscription info, and lacks UI for editing/deleting users.

## Implementation Steps

### 1. Update Frontend Types (src/lib/api/hooks.ts)

- Add subscription fields to `AdminUserRow` interface:
  - `tier`, `subscription_status`, `stripe_customer_id`, `billing_interval`, `current_period_end`, `price_usd`
- These fields are already returned by the backend but TypeScript doesn't know about them

### 2. Enhance Users Table UI (src/routes/admin.tsx - UsersSection)

- Add "Subscription" column showing tier badge (free/student/pro/team) and status
- Add "Actions" column with:
  - **Edit** button → opens modal/dialog
  - **Delete** button → confirmation dialog (with extra confirm for admin users)
- Style subscription badges with colors:
  - free: gray/muted
  - student: blue/brand
  - pro: purple/accent
  - team: gold/premium

### 3. Create Edit User Dialog (new component in admin.tsx)

**Fields:**

- Name (text input)
- Admin status (toggle switch)
- Subscription tier (dropdown: free, student, pro, team)
- Subscription status (dropdown: active, cancelled, past_due, trialing)

**API calls:**

- PATCH `/admin/users/:id` for name + is_admin
- PATCH `/admin/users/:id/subscription` for tier + status
- These endpoints already exist in the backend

### 4. Create Delete User Confirmation (using existing AlertDialog component)

- Warn: "This action cannot be undone"
- If deleting another admin: require extra confirmation (backend enforces this with `?confirm=true`)
- Prevent self-deletion (backend blocks this)
- DELETE `/admin/users/:id` (endpoint exists)

### 5. Add React Query Mutations (src/lib/api/hooks.ts)

```typescript
useUpdateUser(); // PATCH /admin/users/:id
useUpdateUserSubscription(); // PATCH /admin/users/:id/subscription
useDeleteUser(); // DELETE /admin/users/:id
```

- Invalidate `["admin", "users"]` query on success
- Toast notifications for success/error

## Verification

### Build

- `npm run build` succeeds with no TypeScript errors

### Manual Testing (3 viewports)

**Admin Dashboard:**

1. Navigate to `/admin` route
2. Click "Users" section
3. Verify subscription column shows tier badges + status correctly
4. Click "Edit" on a user:
   - Modal opens with current values pre-filled
   - Change name → save → verify update in table
   - Toggle is_admin → save → verify badge change
   - Change subscription tier → save → verify badge update
5. Click "Delete" on a non-admin user:
   - Confirmation dialog appears
   - Confirm → user removed from table
6. Try deleting admin user:
   - Extra confirmation required
7. Try deleting yourself:
   - Blocked with error message

**Responsive:**

- Mobile (375px): Actions overflow to dropdown menu
- Tablet (768px): Table scrolls horizontally if needed
- Desktop (1280px): Full table visible

### Edge Cases

- Non-admin users can't access `/admin` route (already enforced)
- Self-deletion blocked (backend + frontend)
- Deleting another admin requires confirmation
- Optimistic updates + rollback on error
