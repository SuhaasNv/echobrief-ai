# Phase 3: Code Quality Improvements - Implementation Plan

## Context & Findings

### 1. Duplicate Patterns Identified

**Loading Spinners (40+ instances):**

- Pattern: `<Loader2 className="h-5 w-5 animate-spin text-muted-foreground" />`
- Found in: All route files, components
- 3 size variants: h-3/w-3 (buttons), h-4/w-4 (inline), h-5/w-5 (page center)
- **Impact:** Every file imports Loader2 from lucide-react individually

**Date Formatting Functions (12 instances):**

- `formatDate()` - duplicated in 6 files with identical or near-identical logic
- `formatDuration()` - duplicated in 7 files (all identical)
- `formatTimestamp()` - duplicated in 3 files
- All use `toLocaleDateString()` with same options
- **Impact:** Inconsistent date display formats, maintenance burden

**Empty States (implicit pattern):**

- No standardized component, each route implements custom markup
- Found in: action-items, meetings, analytics, chat
- Common elements: centered text, muted foreground, CTA button
- **Impact:** Inconsistent UX, verbose JSX

**Large Route Files (5 files >600 lines):**

1. **app.meetings\_.$id.tsx** (865 lines) - Meeting detail with 10+ helper functions
2. **app.settings.tsx** (703 lines) - 5 section components, 4 helper functions
3. **admin.tsx** (700 lines) - 5 section components, 10+ helpers
4. **app.upload.tsx** (617 lines) - Complex state machine, 4 helper functions
5. **app.analytics.tsx** (272 lines) - Heavy data transformations

**Structure Analysis:**

- **admin.tsx**: 5 large section components (OverviewSection, UsersSection, MeetingsSection, QueueSection, SystemSection) + 10 helpers
- **app.settings.tsx**: 4 sections (ProfileSection, PasswordSection, WorkspacesSection, DangerSection) + WorkspacePicker/ColorPicker/KindToggle
- **app.meetings\_.$id.tsx**: Single massive component with inline helpers and sub-components

### 2. Existing Architecture

- `/src/lib/` has utilities: schemas, api, workspace-store, theme
- `/src/components/app/` for shared app components (app-shell, workspace-switcher, live-recorder)
- `/src/components/ui/` for shadcn/ui primitives
- No `/src/components/shared/` or common patterns directory yet

## Implementation Steps

### Step 1: Create Date Utilities Library

**File:** `src/lib/date-utils.ts` (NEW)

Extract and consolidate:

- `formatDate(iso: string, includeYear?: boolean)` - handles both "MMM DD" and "MMM DD, YYYY"
- `formatDuration(sec: number | null)` - "M:SS" format
- `formatTimestamp(sec: number)` - "MM:SS" format
- `formatUptime(sec: number)` - human-readable uptime (X days Y hours)
- `isOverdue(date: string | null)` - boolean check
- `formatDue(due: string | null)` - "MMM DD" or "No due date"

**Impact:** Eliminates 12 duplicate functions, standardizes date display

### Step 2: Create Shared UI Components

**Files to create:**

#### 2.1 `src/components/shared/loading-spinner.tsx` (NEW)

```tsx
interface LoadingSpinnerProps {
  size?: "sm" | "md" | "lg";
  center?: boolean;
}
```

- Replaces 40+ inline Loader2 instances
- Variants: sm (h-3), md (h-4), lg (h-5)
- Optional `center` prop wraps in centering div

#### 2.2 `src/components/shared/empty-state.tsx` (NEW)

```tsx
interface EmptyStateProps {
  icon?: LucideIcon;
  title: string;
  description?: string;
  action?: { label: string; onClick: () => void };
}
```

- Standardizes empty state UX across all routes
- Used in: analytics, action-items, meetings, chat

## Risk Mitigation

**Low Risk Changes:**

- Date utilities (pure functions, easy to test)
- LoadingSpinner component (visual only)
- EmptyState component (presentational)

**Medium Risk Changes:**

- Extracting settings sections (many state mutations, API calls)
- Extracting admin sections (complex data tables, polling)

**High Risk Changes:**

- Refactoring app.meetings\_.$id.tsx (tight coupling between components)

**Strategy:**

- Start with utilities and shared components (lowest risk)
- Test each section extraction independently
- Keep original files until verification passes
- Run build after each major extraction
