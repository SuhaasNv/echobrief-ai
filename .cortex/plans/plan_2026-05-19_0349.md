# GDPR Compliance Implementation Plan

## Context

Since OAuth/SSO is deferred, the remaining Priority 1 blockers are the two GDPR compliance features:

1. **Account Export (POST /account/export)** - Generate ZIP archive with all user data and email download link
2. **Account Deletion R2 Cleanup (DELETE /account/me)** - Delete all user audio files from R2 bucket

### Key Findings from Exploration

**Current State:**

- Account route has TODO stubs at lines 82-86 (export) and 95-96 (deletion R2 cleanup)
- ON DELETE CASCADE handles database cleanup automatically
- Resend email service is configured and working (RESEND_API_KEY in env)
- R2 operations are available via `src/server/services/r2.ts`
- No ZIP library installed yet (archiver needed for streaming ZIP creation)
- BullMQ queue infrastructure exists for background jobs

**Database Schema (from migrations):**

- User data spans 9 tables: users, workspaces, workspace_members, meetings, transcripts, summaries, action_items, transcript_chunks, pipeline_logs
- Audio files stored in R2 with key pattern: `${userId}/${meetingId}/original.{ext}`
- All child tables use ON DELETE CASCADE, so DB cleanup is automatic

**Audio Storage Pattern:**

- R2 key format: `buildAudioKey(userId, meetingId, ext)` → `userId/meetingId/original.ext`
- Can list all user audio with prefix filter: `${userId}/`
- Cleanup worker already has batch deletion pattern (cleanup-r2.ts)

### **Task 2: Create export-account worker**

**File:** `src/server/workers/export-account.ts` (~180 lines)

**Purpose:** Background job that builds ZIP archive with all user data and uploads to R2 with 7-day expiry

**Structure:**

1. Define `ExportJob` interface: `{ user_id: string; email: string }`
2. Create `exportUserAccount(job: ExportJob)` function that:
   - Queries all user data (meetings, summaries, action items, transcripts)
   - Creates streaming ZIP archive with archiver
   - Adds JSON manifests for structured data
   - Includes metadata.json with export timestamp
   - Uploads ZIP to R2 at `exports/${userId}/${timestamp}.zip`
   - Generates 7-day presigned download URL
   - Sends email with download link via Resend
3. Export function for worker to call

**Data to include in ZIP:**

- `metadata.json` - export timestamp, user info
- `meetings.json` - all meetings with metadata
- `transcripts.json` - all transcripts (raw_text + structured content)
- `summaries.json` - all meeting summaries
- `action_items.json` - all action items
- `pipeline_logs.json` - processing logs with costs
- `workspaces.json` - workspace memberships
- Note: Audio files are too large for ZIP, provide presigned URLs instead

## Trade-offs & Decisions

**Why archiver over jszip?**

- Archiver supports streaming (low memory for large exports)
- Production-ready with 8M+ weekly downloads
- Better error handling for large files

**Why 7-day ZIP expiry?**

- Matches R2 audio retention policy (consistency)
- GDPR requires "without undue delay" (7 days is reasonable)
- Reduces storage costs

**Why not include audio in ZIP?**

- Audio files are too large (meetings can be 100MB+)
- ZIP would timeout or OOM for heavy users
- Instead, include presigned URLs in metadata.json

**Why R2 deletion doesn't block account deletion?**

- GDPR compliance at database level is mandatory
- R2 cleanup is nice-to-have (files auto-expire in 7 days anyway)
- Failed R2 deletion can be retried manually

**Why synchronous R2 deletion vs queue?**

- Account deletion is rare operation
- User expects immediate effect
- R2 batch delete is fast (<5s for 100s of files)
- Simpler than managing delete queue
